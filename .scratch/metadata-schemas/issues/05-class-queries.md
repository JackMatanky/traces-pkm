# 05 — Class Queries (query.from_class / tasks.from_class)

**What to build:** Query and task templates can filter by File Class the same way they filter by tag or folder: `query.from_class("book")` selects Notes whose File Class matches `book`, `query.from_class(["book", "movie"])` matches any of the listed classes, and the same forms exist on `tasks` (`tasks.from_class(...)`). Class matching is is-a transitive (a note whose class extends `book` matches a `book` query). A class with no Schema degrades to exact match with a warning, so missing Schemas fail soft rather than hard.

**Blocked by:** 01 — Config Surface; 02 — Schema Registry and Field Resolution

## Agent Brief

**Category:** enhancement
**Summary:** Add `from_class` source selection to the `query` and `tasks` template namespaces with transitive is-a matching, soft degradation for missing Schemas, and a hard error for `global`.

**Current behavior:**
`QueryOps` registers `query` and `tasks` namespaces whose methods start a query with `all()`, `from_tags(tag)`, or `from_folder(folder)`, matching `QuerySource`'s variants (`All`, `Tag`, `Folder`). There is no class-based source, and nothing reads a Note's File Class from frontmatter during query.

**Desired behavior:**
- `query.from_class("book")` selects Notes whose File Class (frontmatter key from `[schemas] class_field`, default `class`) matches `book`.
- `query.from_class(["book", "movie"])` matches any of the listed classes.
- `tasks.from_class(...)` mirrors both forms for task-level queries.
- Matching is is-a transitive (a note whose class extends `book` matches a `book` query), via ticket 02.
- A class with no Schema degrades to exact match with a warning — matching then falls back to the class value alone.
- `from_class("global")` hard-errors — `global` is forbidden as a Note's File Class per the reserved global Schema rules.

**Key interfaces:**
- `QuerySource::Class(Vec<String>)` — new variant alongside `All`, `Tag`, `Folder`, with `is_match` reading the Note's frontmatter class value and checking transitive ancestors from the resolution engine.
- `from_class` method on the `QueryOps` namespace object, registered in `METHODS`.
- Degradation path producing a warning for classes with no Schema.

**Out of scope:**
- The `schema` namespace and `file`-field filtering (tickets 03/04) — though the file-field `class` filter reuses this same transitive matching.
- QueryOutcome transformation logic — unchanged.
- General metadata field filtering with comparison operators — stays QueryOutcome's `.where()`/`.filter()`.
