- [ ] **OPEN DECISION (X4) — register entry 17, or a `TryFrom` refactor first.** Spec's D14 line is absolute ("`None` … surfaces as an error, never a silent shift"), but `From<DateValue> for DateTimeValue` (`src/date.rs:741-749`) falls back to UTC midnight on zone failure (`unwrap_or_else(|_zone_failure| midnight.and_utc())` at `:747`) and is reachable from filter equality (`is_equal_to_date` `src/date.rs:681-683` — `Date == DateTime` would compare at UTC midnight while every other path returns `DateError::LocalZoneLookup`). Options with evidence: **(a)** keep `From`, register the fallback as divergence #17 and amend the rustdoc (its current "chrono does the same" is a parity claim, not a spec claim); **(b)** switch to `TryFrom` — but note the promotion's production surface is wider than equality: sort-key coercion (`src/query/sort.rs:375`, `:396`) and cross-type ordering (`src/note/field.rs:269-272`) also call it, and `Ordering::cmp` cannot propagate an error, so `TryFrom` forces either a declared fallback there too or a rework of the rank comparison — (a) is likely the honest answer, (b) is only cheap if the test/fixture grep surprises us. Spec's D14 line already carries this question; do not resolve it in the glossary text without picking one first.
- [ ] **OPEN DECISION (U1/F1) — `,` has two grammar owners; pin the precedence and register it (entry 18).** Duration claims `,` as a part separator (module doc `src/duration.rs:5`, `parse` docs `:141-142`, `skip_separators` admits `,` at `:183`/`:263`); the note-parser claims `,` as the list delimiter (`src/note/parser/inline.rs:67,82`, `parse_comma_list_from` `:91`); YAML splits lists *before* coercion (`src/note/field.rs:656` test `list: [1h, 30m]` → two durations). At the inline seam duration is tried before the list path, so first-atom priority decides — PREDICTED (traced, not executed): `key:: 1h, 30m` → **one** `Duration(5400s)` (the lookahead eats `", "`); `1h, 45` → **`String("1h, 45")`**; `1h,` → `List([Duration(1h)])`. No test, ticket, or register entry covers this today. Options: **(a)** keep duration-wins, pin all five outcomes with tests, register as divergence; **(b)** try the list path first when a `,` follows a complete atom with remaining content (note-parser precedence change, not a `duration.rs` change). Probe cost either way: ~5 asserts in `inline.rs` tests + one register entry. This ticket *records* the decision; the implementation side (if any test changes are needed) can ride here or hand back to 04 — say which.
