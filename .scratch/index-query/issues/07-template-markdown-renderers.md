# 07 — Template Markdown Renderers

**What to build:** Templates can render QueryOutcome values as markdown tables, markdown lists, markdown task lists, and counts through terminal methods and pipeline filters. Template loops remain the escape hatch for custom value transformations.

**Blocked by:** 06 — QueryOps Template Namespace, 09 — Task-Level Queries

**Status:** completed

- [x] QueryOutcome can render a markdown table from field path columns.
- [x] QueryOutcome can render a markdown list from field path values.
- [x] Task-level QueryOutcome values can render markdown task lists.
- [x] QueryOutcome can render a count.
- [x] Terminal renderers work as QueryOutcome methods.
- [x] Terminal renderers work as pipeline filters.
- [x] Tests show `{% for %}` loops can format transformed values that terminal renderers do not handle.

### Implementation Notes

- **`QueryOutcome::table`/`list`/`task_list`** (`src/index/query.rs`): plain
  Rust methods with no minijinja dependency, added alongside the existing
  `filter`/`sort`/`limit`/`group_by`/`flatten` transformations — same
  reasoning as #06's `Object` split: the index module stays reusable by #08's
  future CLI query commands.
  - `table(headers: &[&str], columns: &[&str]) -> Result<String, QueryError>`
    pairs each header label with the field path at the same position,
    matching `CONTEXT.md`'s pre-existing `Pipeline Query` example
    (`table(["Name", "Rating"], ["file.name", "rating"])`) rather than
    inventing a divergent single-list signature. Headers and columns must
    have equal length (new `QueryError::TableColumnMismatch`). Cell values
    render through a private `field_text`/`table_cell_text` helper pair:
    `Null` → empty string, `List`/`Object` flatten recursively joined by
    `", "`, `Link` renders its target path. Table cells additionally escape
    `|` and collapse `\n` to a space so no cell value can corrupt the row
    structure.
  - `list(path: &str)` renders one bullet per record, unescaped (no table
    structure to protect).
  - `task_list()` renders `- [ ]`/`- [x]` per task-level record; a
    page-level record (no `task.*` fields) returns the new
    `QueryError::TaskListOnPageRecords` instead of silently producing a
    misleading empty/partial list.
  - `count` has no new domain method — `QueryOutcome::len` (already public)
    is reused directly from both the minijinja call-method and filter forms.
- **Dual API** (`src/template/engine/query.rs`, ADR-0005): `QueryOutcome`'s
  `call_method` gets an early-return terminal-method branch (`table`,
  `list`, `task_list`, `count`) ahead of the existing non-terminal chain
  (`where`/`filter`/`sort`/`limit`/`group_by`/`flatten`), since terminal
  methods return `String`/`usize` instead of another chainable
  `QueryOutcome`. A new `register_filters` free function registers
  `table`/`list`/`task_list`/`count` as pipeline filters once (not per
  `QueryOps` instance) in `TemplateEngine::new`.
  - `table`'s minijinja-facing signature took two iterations: `Rest<&str>`
    variadic args fail minijinja's `Function` trait bound (`Function`
    requires every parameter type implement `ArgType` for *every* lifetime,
    which a borrowed `Rest<&str>`/`Vec<&str>` cannot satisfy — only owned
    `String` can); and even the call-method form's `from_args` cannot borrow
    a `Vec<&str>` out of a minijinja list-literal argument value at all
    (`"type conversion is not legal in this situation (implicit borrow)"`).
    Both the call-method and filter forms build owned `Vec<String>` first
    and borrow `&str` slices from that before calling
    `QueryOutcome::table`.
- **Tests**: `src/index/query.rs` gets `mod table`/`mod list`/`mod
  task_list` (header/separator/row shape, pipe-escaping, newline-collapsing,
  empty-outcome, malformed-field-path, and the new headers/columns-mismatch
  case) — no minijinja/CLI setup needed, per the spec's testing decisions.
  `src/template/engine/query.rs` gets a `mod terminal_rendering`
  (call-method and filter forms render identically for all four terminal
  renderers, plus an empty-headers/columns smoke case), a `mod
  for_loop_escape_hatch` (`{% for %}` applying `| upper` — something
  `table`/`list` cannot express since they take field path strings, not
  minijinja expressions), and three new `mod errors` cases (`task_list` on
  page-level records, and the headers/columns length mismatch).
- **Smoke test**: built the binary, ran `traces init`, `traces trust`, and
  `traces template` against a real trusted project with two `#book`-tagged
  Notes (one with two tasks) using all four renderers in both call-method
  and filter forms plus a `{% for %}` + `| upper` escape-hatch line.
  Rendered output confirmed custom table headers (not raw field paths),
  correct number formatting (`9`, not minijinja's `9.0`, since terminal
  renderers format through plain Rust `f64` `Display` rather than
  minijinja's `Value` `Display`), matching counts from both call forms, and
  correct task checkboxes.
- **Code review** (`/code-review`, Standards + Spec parallel sub-agents
  against `main`): Spec review found the diff fully faithful — no missing
  acceptance criteria, no scope creep into #08/#09, `table`'s two-list

  exposed both ways, non-terminal ops verified untouched. Standards review
  found no hard violations; two Fowler judgement-call findings — a small
  `Vec<String>`→`Vec<&str>` conversion duplicated between `call_method`'s

  `field_text` (index/query.rs) shadows the pre-existing `field_value`
  (template/engine/query.rs) FieldValue match — left as-is since the two
  return different types (`String` vs minijinja `Value`) with intentionally
  different numeric formatting, and merging them would cross the
  documented index↔minijinja module boundary (see this module's own
  "Object Boundaries" doc section) for a cosmetic gain.
