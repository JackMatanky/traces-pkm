# 02 — Markdown Note Metadata Extraction

**What to build:** Markdown Notes add `Note` records to the FileIndex using markdown structure from `pulldown-cmark` events. The first complete vertical slice should index YAML metadata blocks, lists (with task completion state), wikilinks/outlinks, and the parser state needed to exclude code regions from later Inline Field extraction. Tasks are exposed via a `Note::tasks()` accessor over indexed list items.

**Blocked by:** 01 — FileIndex Baseline

**Status:** ready-for-agent

- [ ] List and list item structure is extracted with task completion status.

- [ ] Wikilinks or markdown links are indexed as outlinks.

### Implementation Notes

- **Module Architecture**: `src/index/markdown/` structured as a directory module separating domain models (`types.rs`) from parsing logic (`parser.rs`).
- **Domain Types (`src/index/markdown/types.rs`)**:
  - `Note`: Primary type containing project-relative `path: PathBuf`, `frontmatter: Option<Frontmatter>`, `lists: Vec<List>`, `outlinks: Vec<Outlink>`, and `code_regions: Vec<CodeRegion>`. Exposes `Note::tasks(&self)` yielding an iterator over top-level and nested task items. (Eliminated separate `NoteRecord` wrapper).
  - `Frontmatter`: Wraps raw YAML block text string.
  - `Outlink`: Stores `target`, `text`, and `kind: LinkType` (`LinkType::Markdown` vs `LinkType::Wikilink`).
  - `List` & `ListItem`: Hierarchical representation of ordered/unordered lists with `task_status: Option<TaskStatus>` (`Incomplete` vs `Complete`).
  - `CodeRegion`: Byte range (`Range<usize>`) of inline code spans and fenced code blocks for excludable regions in ticket #03.
  - `FileFormat`: Enum classification (`FileFormat::Note` vs `FileFormat::Other`), replacing prior `FileKind`.
- **Parsing (`src/index/markdown/parser.rs`)**:
  - Pure function `parse_markdown(path: impl Into<PathBuf>, &str) -> Note` over `pulldown-cmark` event stream with `ENABLE_TASKLISTS | ENABLE_YAML_STYLE_METADATA_BLOCKS | ENABLE_WIKILINKS`.
  - Uses stack frame parsing (`ListFrame`, `ItemFrame`) for nested lists to arbitrary depth without intermediate allocations.
- **Persistence (`src/index/store.rs`)**:
  - Added `NOTES: TableDefinition<&str, &[u8]>` redb table.

## Agent Brief

**Category:** enhancement
**Summary:** Layer `Note` records onto the `FileIndex` for markdown files. Parse each `FileKind::Markdown` file using `pulldown-cmark` into a `Note` struct storing YAML frontmatter, `List`/`ListItem` structure (with task completion state), outlinks (markdown links and wikilinks), and parser state for code-region byte ranges (to exclude them in #03). Persist to a `notes` redb table keyed by path. `tasks()` is a method on `Note` that derives task list items.

**Blocked by:** #01 (unmerged in `.worktrees/fileindex-baseline`): needs `FileIndex`, `FileRecord`/`FileKind::Markdown`, `IndexStore`. Do not start until #01 merges.

**Key interfaces:**
- `index/markdown.rs`: pure function `&str -> Note` over `Parser::new_ext(src, opts).into_offset_iter()`. Opts: `ENABLE_TASKLISTS | ENABLE_YAML_STYLE_METADATA_BLOCKS | ENABLE_WIKILINKS`.
- `Note { frontmatter, lists, outlinks }` (plus internal code-region byte ranges for #03).
- `Note::tasks()` method filtering list items that carry task completion state.
- Extend `IndexStore` with the `notes` table; `FileIndex::build` parses markdown files and `persist`/`load` round-trip both `file_records` and `notes` tables.

**Acceptance criteria:**
- [ ] Markdown Notes store a `Note` record in the `notes` table in addition to their `FileRecord`.
- [ ] YAML frontmatter metadata blocks are extracted into `Note`.
- [ ] List and list item structure is extracted with task completion status.
- [ ] `Note::tasks()` accessor returns task list items derived from indexed lists.
- [ ] Wikilinks and markdown links are indexed as outlinks.
- [ ] Parser tests verify code block and inline code byte ranges are tracked as excludable regions for #03.
- [ ] `notes` redb table survives build, persist, and load round-trips in `FileIndex`.

**Out of scope:**
- Inline fields and tags (ticket #03).
- Inlinks (ticket #10).
- Lazy query refresh (ticket #04).
- QueryOps namespace or CLI query commands (`list`/`table`/`task`).
