## Agent Brief

**Category:** enhancement
**Summary:** Polish the template and CLI query surfaces with clear error diagnostics and end-to-end test coverage after all upstream tickets merge.

**Current behavior:**
Query failures surface as raw minijinja render errors (templates) or `CliError::Query`/`CliError::Index` (CLI) with no template-line context or "what to do next" guidance. Integration test coverage exists per-ticket (index, template, CLI, inlinks separately) but no suite exercises the full stack: index a project → query via template QueryOps → query via CLI → verify inlink behavior → confirm diagnostics on bad input.

**Desired behavior:**
- Template query errors identify the failing template context (name, line/column) so the author can fix the exact template line.
- CLI query errors explain what failed and what the user can do next.
- An end-to-end test suite covers: indexing, template QueryOps usage, page CLI queries (`list`/`table`), task CLI queries, inlink behavior, and error cases.
- Common spec workflows (user stories 49-56) are demonstrated through runnable tests.
- No module exposes `redb` internals to template or CLI callers (verify, don't rebuild).

**Key interfaces:**
- `QueryError` (`src/index/query/error.rs`) — the error type template and CLI callers already receive; may need richer variants or display formatting.
- `CliError::Query` / `CliError::Index` (`src/cli/error.rs`) — CLI error wrapping; may need "did you mean?" suggestions or context annotations.
- Template rendering seam (`src/template/engine/`) — where template-line context is available and should be attached to errors.
- The existing per-ticket integration tests in `src/index/mod.rs`, `src/cli/task.rs`, `src/cli/list.rs`, `src/cli/table.rs`, and `src/template/engine/query.rs` as the pattern to follow for end-to-end coverage.

**Out of scope:**
- JSON output (spec user story 56, explicitly deferred).
- Rich terminal rendering beyond minimum useful output.
- Dataview Query Language parser or calendar queries.
- Changes to upstream tickets (#07-#11) — this ticket consumes their merged state.
