## Agent Brief

**Category:** enhancement
**Summary:** Add `traces list` and `traces table` page-level query subcommands, mirroring the existing `traces task` command shape.

**Current behavior:**
The CLI offers `traces index` (rebuild the persisted FileIndex), `traces task`
(task-level queries), `traces template`, plus trust/init/completions. There
are no page-level query commands: `traces list` and `traces table` are not
registered in the CLI `Commands` enum. The underlying pieces exist and are
reusable — `FileIndex::refresh` returns a freshly-indexed `FileIndex`,
`FileIndex::query` produces a page-level `QueryOutcome` from a `Source`
(all / tag / folder), and `QueryOutcome` already supports filtering, sorting,
limiting, and the `table`/`list` terminal renderers.

**Desired behavior:**
`traces list` and `traces table` are top-level subcommands that accept the
same flags as `traces task`: `--from` (a `#tag`, including nested sub-tags, or
a folder path; omitted means all pages) and `--where <filter expression>`.
Commands use flags, not a Dataview Query Language parser. Both refresh stale
FileIndex entries before querying (`FileIndex::refresh`). Primary output goes
to stdout; diagnostics and the result count go to stderr.

- `traces list` prints one markdown bullet per matching page (the page-level
  `QueryOutcome::list` renderer).
- `traces table` prints a markdown table readable in a terminal (the
  page-level `QueryOutcome::table` renderer), with columns supplied by flags.
- An untrusted project root fails with the existing `CliError::ConfigLoad`
  path; a refresh failure wraps as `CliError::Index`; an unparsable `--where`
  expression wraps as `CliError::Query` (the variant `traces task` already
  produces).

**Key interfaces:**
- `Commands` enum (`src/cli/mod.rs`) — add `List` and `Table` variants plus
  dispatch arms, following the existing `Index`/`Task` wiring.
- New `#[derive(Debug, clap::Args)]` structs per command — mirror the
  `task::Task` flags (`--from`, `--where`), and any flags needed to name table
  columns.
- `FileIndex::query(&Source)` — the page-level query seam (same visibility as
  the already-CLI-used `query_tasks`).
- `QueryOutcome::table(headers, columns)` and `QueryOutcome::list(path)` —
  reuse the #07 renderers directly; report row counts via `QueryOutcome::len`.
- `Source` selection logic — reuse the `#`-prefix → tag / else folder /
  omitted → all mapping `traces task` already implements.

**Acceptance criteria:**
See the checklist at the top of this ticket.

**Out of scope:**
- `traces task` (already exists; #09).
- JSON output (spec user story 56; explicitly out of scope).
- Rich terminal table rendering beyond the minimum useful table output.
- A Dataview Query Language parser, calendar queries, or a file watcher.

### Implementation Notes

- **`traces list`** (`src/cli/list.rs`, new): `--from`/`--where` (mirroring
  `task::Task`), refreshes the `FileIndex`, renders the page-level
  `QueryOutcome::list("file.path")` to stdout, `"<n> page(s) from <root>"`
  to stderr. `List::render` is split from `List::run` so tests assert on
  rendered content without capturing process stdout, matching the
  `task::Task::lines`/`Task::run` split.
- **`traces table`** (`src/cli/table.rs`, new): same `--from`/`--where`,
  plus a repeatable `--column <field>` (`required = true`, at least one
  occurrence) — the field path text doubles as that column's header, so
  `--column file.path --column rating` needs no separate header-naming
  syntax. Renders `QueryOutcome::table(&columns, &columns)`.
- **`--sort <field>` / `--order <asc|desc>`** (both commands, default
  `asc`): not in this ticket's original flag list, but ADR 5's own worked
  example (`traces table "rating, author" --from "#book" --sort "rating"
  --desc`) shows sort flags the ticket's acceptance checklist dropped
  without explanation. Added to close that gap. `--order` is
  `index::SortOrder` (`src/index/query/sort.rs`), a `clap::ValueEnum` with
  `#[value(name = "asc")]`/`#[value(name = "desc")]` overrides for the
  shortened values — defined where sort-direction semantics already live
  (next to `sort_key_cmp`), not duplicated per CLI command. Rust/Template
  callers keep the pre-existing bool-based `QueryOutcome::sort`/`group_by`
  (the Dataview-style boolean convention #06/#07 already shipped against);
  `SortOrder::is_descending()` bridges the CLI enum to that bool.
- **`Commands` enum wiring** (`src/cli/mod.rs`): `List`/`Table` variants
  and dispatch arms alongside the existing `Index`/`Task`, module
  declarations kept alphabetical (`list`, `table` sort before `task`).
- **`Source::from_flag`** (`src/index/query.rs`, new `impl Source` method):
  the `#`-prefix → tag / else folder / omitted → all mapping was
  triplicated verbatim across `task.rs`, `list.rs`, and `table.rs` as a
  private `source()` method on each command struct. Consolidated onto
  `Source` itself so all three CLI commands call
  `Source::from_flag(self.from.as_deref())` directly — no more per-command
  duplication, and `task.rs` (from #09) was updated too for consistency.
- **Table rendering — two iterations:**
  1. First pass hand-rolled nushell-style column-width alignment directly
     in `QueryOutcome::table` (char-count padding, `ponytail:`-flagged as
     not accounting for double-width glyphs).
  2. Replaced with `comfy-table`'s `ASCII_MARKDOWN` preset
     (`Cargo.toml`: `comfy-table = { version = "7.2.2", default-features =
     false }` — disables the `tty` feature, which drops the `crossterm`
     dependency and its one `unsafe` terminal-size `ioctl` call; only
     `unicode-segmentation`/`unicode-width` remain). Gives correct
     display-width column alignment instead of the char-count
     approximation. `comfy-table` is not markdown-aware, so `|`/newline
     escaping for both headers and cell values still lives in
     `QueryOutcome::table` (via a new shared `escape_table_text` helper).
  - This also fixed a real gap: header escaping had been hand-duplicated
    in `cli/table.rs` (reimplementing `table_cell_text`'s private escape
    rule) and was *never* applied to Template callers, who could pass an
    unescaped `|` straight into a header. Escaping now happens once,
    inside `QueryOutcome::table` itself, for both callers.
  - Deleted `markdown_row` (`src/index/query.rs`), which the `comfy-table`
    swap left genuinely dead — caught via `index/mod.rs`'s module-wide
    `#![cfg_attr(not(test), expect(dead_code, ...))]`, written anticipating
    this ticket. Confirmed the suppression is still needed for other
    legitimately-unwired items (`FileIndex::notes`, `FileRecord::created_at`,
    `Timestamp` helpers, `QueryOutcome::is_empty`/`r#where`) and kept it
    with an updated reason.
- **Tests:**
  - `src/cli/list.rs`, `src/cli/table.rs`: `mod render` (source/filter/sort
    wiring, malformed-field-path and unparsable-filter rejection, header
    pipe-escaping, empty-header edge case) and `mod run` (trusted/untrusted
    project root, mirroring `task.rs`'s fixtures).
  - `src/cli/mod.rs`: argv dispatch tests for `list`/`table`, `--column`
    required-at-least-once, `--order` accepting the shortened `asc`/`desc`
    and rejecting the unshortened `ascending` spelling.
  - `src/index/query.rs`: `Source::from_flag` unit tests, a header
    pipe-escaping regression test on `QueryOutcome::table`.
  - `src/index/query/sort.rs`: `SortOrder` default/`is_descending` tests.
- **Code review** (`/code-review`, Standards + Spec parallel sub-agents
  against `main`): both axes reported "correct." Spec review's one real
  finding (table headers weren't escaped like data cells) was fixed before
  the final commit; a second, low-confidence note (headers read as raw
  field paths, e.g. `file.modified_at`, rather than a human label) was
  accepted as the minimal reading of the ticket's underspecified "table
  column flags" requirement. Standards review found no hard violations,
  only excused judgement-calls (duplication mirroring the established
  `task.rs` sibling-file convention).
- **Verification**: `cargo +nightly fmt --all -- --check`, `cargo clippy
  --lib -- -D warnings`, `cargo test --workspace` — **1083/1083 lib tests
  passing** plus bin/integration/doctests. Manually smoke-tested the built
  binary: `traces list`, `traces list --from '#tag'`, `traces table
  --column ... --sort ... --order desc`, a `--column` value containing `|`
  rendering with an escaped header, `--order ascending` correctly rejected
  (shortened-only), and stdout/stderr piped separately to confirm the
  split.
- **Out of scope, deliberately not touched**: JSON output, a Dataview
  Query Language parser, calendar queries, a file watcher, and rich
  terminal rendering beyond column alignment (no box-drawing borders, no
  ANSI color, no terminal-width wrapping/truncation) — `comfy-table`'s
  `tty` feature (which would enable width auto-detection and styling) is
  explicitly disabled.
