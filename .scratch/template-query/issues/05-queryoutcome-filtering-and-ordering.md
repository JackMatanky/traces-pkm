### Implementation Notes

- **Field path resolution (`src/index/query.rs`)**:
  - Added `IndexRecord::field(&self, path: &str) -> Result<FieldValue, QueryError>`, parsing `path` once into an internal `FieldPath` (`File(FileField)`, `Metadata(String)`, or `Tags`) and resolving it against `FileRecord`/`Note`.
  - `file.*` accessors: `path`, `name`, `folder`, `size`, plus Dataview-style `ctime`/`cdate`/`mtime`/`mdate` (with `created_at`/`modified_at` as aliases for `ctime`/`mtime`). Added `Timestamp::to_rfc3339`/`to_date_string` in `src/index/file.rs` to back these.
  - Frontmatter/inline fields resolve by bare key through `Note::fields()` (frontmatter wins ties); `tags` resolves to a `FieldValue::List` of tag strings.
  - A record simply missing a well-formed field resolves to `FieldValue::Null`, not an error; only malformed paths (empty, unknown `file.*` accessor, unexpected `.` structure) return `QueryError::UnknownFieldPath`.
- **`QueryOutcome::filter(expr)`**: parses `"<field> <op> <value>"` (`==`, `!=`, `>=`, `<=`, `>`, `<`; value a quoted string, number, or bool) via `CompareOp`/`parse_filter_expr`. `==`/`!=` normalize `String`/`Date`/`Duration` field kinds by text (`fields_equal`), matching the text-based ordering `compare_field_values` already used, so a quoted literal matches a `Date`-typed field like `file.mtime`. Malformed expressions return `QueryError::UnparsableFilterExpression`.
- **`QueryOutcome::sort(path, descending)`** / **`QueryOutcome::group_by(path)`**: share `sort_by_field`, a stable sort keyed by the resolved field value; `FieldValue::Null` always sorts last regardless of direction. `group_by` is the ascending case, clustering equal values so a consumer can detect group boundaries between adjacent records.
- **`QueryOutcome::limit(n: i64)`**: returns `Result`, rejecting negative/overflowing `n` with `QueryError::NegativeLimit` (the ticket's "invalid limit values" case).
- **`QueryOutcome::flatten(path)`**: explodes a `FieldValue::List` field into one row per element via a per-record `(FieldPath, FieldValue)` override consulted first by field resolution; an empty list drops the row, a non-list value passes through unchanged.
- Exposed only `filter` (not a separate `where`), since `where` is a Rust reserved keyword — a future #06 QueryOps namespace can register both the `"where"` and `"filter"` template-facing names against this one method.
- All five transformation methods consume `self` and return a new `QueryOutcome`, so chaining never clones the record vector; `flatten` clones only the `n - 1` extra `IndexRecord`s a real explosion requires.

## Agent Brief

**Category:** enhancement
**Summary:** Add query transformation methods (`where`/`filter`, `sort`, `limit`, `group_by`, `flatten`) to `QueryOutcome`.

**Current behavior:**
`QueryOutcome` is defined (in Issue #04) as an iterable page-level collection of `IndexRecord` query results containing general `FileRecord` fields and parsed markdown `Note` metadata. However, `QueryOutcome` only provides basic inspection accessors (`len`, `is_empty`, `get`, `iter`) and lacks data transformation methods.

**Desired behavior:**
`QueryOutcome` should support method-chained transformations for narrowing, sorting, capping, grouping, and flattening indexed page records. Non-terminal operations take field path selectors or filter criteria and return a new transformed `QueryOutcome` instance. Invalid inputs (such as malformed field paths, missing fields, or invalid limit values) return clear, descriptive errors without panicking.

**Key interfaces:**
- `QueryOutcome` — should provide transformation methods: `where(...)`, `filter(...)`, `sort(...)`, `limit(...)`, `group_by(...)`, and `flatten(...)`.
- `IndexRecord` — field resolution helper to look up fields by path (e.g. `file.name`, `file.folder`, `file.mtime`, frontmatter fields, inline fields, tags).
- Transformation error handling — returns clear error types/messages rather than panicking on invalid inputs.

**Acceptance criteria:**
- [x] `QueryOutcome` can filter Notes with `where` or `filter` expressions.
- [x] `QueryOutcome` can sort Notes by indexed fields (ascending/descending).
- [x] `QueryOutcome` can limit the number of returned rows.
- [x] `QueryOutcome` can group Notes by indexed fields.
- [x] `QueryOutcome` can flatten nested list-like metadata (e.g. list items or multi-value fields) into individual rows.
- [x] Invalid transformation inputs produce clear errors rather than panics.
- [x] Non-terminal transformation methods support method chaining on `QueryOutcome`.

**Out of scope:**
- Registering the `QueryOps` minijinja namespace Object or pipeline terminal filters (belongs to #06).
- Terminal formatting (`table`, `list`, `task_list`, `count`) and CLI query commands (belongs to #06/#07).
- Modifying `FileIndex` freshness or redb persistence logic.
