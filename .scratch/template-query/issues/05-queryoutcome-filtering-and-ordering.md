# 05 — QueryOutcome Filtering and Ordering

**What to build:** QueryOutcome supports enough query transformations for Template and CLI callers to narrow, order, group, and flatten indexed Notes.

**Blocked by:** 04 — Fresh Query Source Selection

**Status:** ready-for-agent

## Agent Brief

**Category:** enhancement
**Summary:** Add query transformation methods (`where`/`filter`, `sort`, `limit`, `group_by`, `flatten`) to `QueryOutcome`.

**Current behavior:**
`QueryOutcome` is defined (in Issue #04) as an iterable page-level collection of `IndexRecord` query results containing general `FileRecord` fields and parsed markdown `Note` metadata. However, `QueryOutcome` only provides basic inspection accessors (`len`, `is_empty`, `get`, `iter`) and lacks data transformation methods.

**Desired behavior:**
`QueryOutcome` should support method-chained transformations for narrowing, sorting, capping, grouping, and flattening indexed page records. Non-terminal operations take field path selectors or filter criteria and return a new transformed `QueryOutcome` instance. Invalid inputs (such as malformed field paths, missing fields, or invalid limit values) return clear, descriptive errors without panicking.

**Key interfaces:**
- `QueryOutcome` — should provide transformation methods: `where(...)`, `filter(...)`, `sort(...)`, `limit(...)`, `group_by(...)`, and `flatten(...)`.
- `IndexRecord` — field resolution helper to look up fields by path (e.g. `file.name`, `file.folder`, `file.mtime`, frontmatter fields, inline fields, tags).
- Transformation error handling — returns clear error types/messages rather than panicking on invalid inputs.

**Acceptance criteria:**
- [ ] `QueryOutcome` can filter Notes with `where` or `filter` expressions.
- [ ] `QueryOutcome` can sort Notes by indexed fields (ascending/descending).
- [ ] `QueryOutcome` can limit the number of returned rows.
- [ ] `QueryOutcome` can group Notes by indexed fields.
- [ ] `QueryOutcome` can flatten nested list-like metadata (e.g. list items or multi-value fields) into individual rows.
- [ ] Invalid transformation inputs produce clear errors rather than panics.
- [ ] Non-terminal transformation methods support method chaining on `QueryOutcome`.

**Out of scope:**
- Registering the `QueryOps` minijinja namespace Object or pipeline terminal filters (belongs to #06).
- Terminal formatting (`table`, `list`, `task_list`, `count`) and CLI query commands (belongs to #06/#07).
- Modifying `FileIndex` freshness or redb persistence logic.
